# Участие в TRADR

Спасибо за улучшения проекта. Перед началом работы ознакомьтесь с [локальным запуском](./DEVELOPMENT.md) и архитектурными границами в [ARCHITECTURE.md](./ARCHITECTURE.md).

## Перед изменением

1. Сформулируйте цель и затронутую предметную область.
2. Проверьте, нет ли незавершённых изменений в тех же файлах.
3. Для заметной функции или изменения контракта сначала согласуйте короткий план.
4. Не добавляйте секреты, пользовательские данные и файлы окружения в Git.

## Принципы кода

- Один класс — одна ответственность.
- Инкапсулируйте состояние и правила предметной области.
- Предпочитайте композицию наследованию.
- Не оставляйте мёртвый код, временные заглушки и неиспользуемые зависимости.
- Не смешивайте DTO, HTTP-логику и бизнес-правила.

## Проверка

Перед передачей изменений выполните проверку, которая соответствует затронутому слою:

```bash
npm run test:web
npm run test:backend
```

Если изменение влияет на оба приложения, запустите также полный локальный контур через `npm run dev` и проверьте `/health`.

## Описание изменения

В описании укажите:

- что изменилось для пользователя или системы;
- какие модули затронуты;
- как это проверено;
- какие ограничения или последующие шаги остаются.
