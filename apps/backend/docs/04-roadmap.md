# Roadmap до MVP

Ты выбрал закрыть все экраны сайта бэкендом в первой версии — окей, но это
означает 9 фаз, а не одну. Правило простое: **не начинаешь фазу N+1, пока
фаза N не работает end-to-end** (запущено локально, экран на фронте реально
дёргает эндпоинт и показывает не-моковые данные). Если тянет перепрыгнуть —
это и есть "распыление", про которое тебе уже сказано отдельно: здесь оно
происходит внутри одного проекта, но эффект тот же — ничего не доведено до
конца, всё "почти работает".

Критерий готовности фазы — не "код написан", а "экран X на фронте больше
не импортирует `lib/fixtures.ts` / `lib/agentsData.ts` / `lib/tradingExtra.ts`
/ `lib/psychologyData.ts` для соответствующих данных". Список конкретных
файлов/экспортов на замену — `05-frontend-integration.md`.

## Phase 0 — Скелет

- Spring Boot проект в `backend/` (Web, Security, Data JPA, PostgreSQL,
  Validation, WebSocket, Flyway)
- `docker-compose.dev.yml` уже готов (`backend/docker-compose.dev.yml`) —
  подними Postgres первым делом
- Flyway baseline-миграция (пустая схема + расширения, если нужны)
- `GET /actuator/health` или свой `/health` — просто чтобы было видно, что
  процесс жив
- `Dockerfile` для самого бэкенда (даже если не деплоишь его прямо сейчас —
  пиши сразу контейнеризуемо)
- **Готово, когда:** `docker compose up`, `./mvnw spring-boot:run` (или
  gradle-эквивалент), `curl localhost:8080/health` отвечает 200.

## Phase 1 — Auth и аккаунты

- `User`, `RefreshToken`, `Account` (миграции + JPA-энтити)
- `POST /auth/register`, `/login`, `/refresh`, `/logout`, `GET /auth/me`
- Spring Security: JWT-фильтр, BCrypt для паролей
- На фронте: **новые экраны логина/регистрации** (их сейчас нет вообще —
  не забудь, что это не "бэкенд-only" фаза, нужен и UI)
- **Готово, когда:** можно зарегистрироваться, получить токен, `GET /auth/me`
  возвращает настоящего пользователя вместо захардкоженного "Ярослав" в
  `Sidebar.tsx`.

## Phase 2 — Рынок

- `Instrument`, `Candle` (миграции), сид 6 тикеров из `fixtures.ts: assets`
- `SyntheticMarketDataProvider` — портирует `buildCandles()`/`useTicker.ts`
- Tick-движок (без агентов пока — только цены)
- `GET /market/indices`, `/instruments`, `/instruments/{ticker}`,
  `/instruments/{ticker}/candles`, `WS /ws/market/{ticker}`
- **Готово, когда:** экраны Рынок и Терминал (график) показывают цены из
  БД, а не из `fixtures.ts`, и цена реально тикает через WebSocket.

## Phase 3 — Ордера, сделки, портфель

- `Order`, `Trade`, `Position` (миграции)
- Порт `OrderCalculator.ts` → Java 1:1, тесты 1:1 с `OrderCalculator.test.ts`
  (это не "вдохновлено", а тот же алгоритм и то же округление — любое
  расхождение в копейках здесь — баг, а не деталь)
- `POST /orders/preview`, `POST /orders`, `GET /orders`, `DELETE /orders/{id}`,
  `GET /trades`, `GET /portfolio`, `GET /portfolio/{ticker}`
- **Готово, когда:** можно вручную выставить заявку через Терминал, она
  исполняется, появляется в Портфеле и Истории сделок — без единой моковой
  строки на этих экранах.

## Phase 4 — Агенты

- `Agent`, `AgentConfig`, `AgentDecisionLog` (миграции)
- Три стратегии (`AggressiveStrategy`, `CarefulStrategy`, `RandomStrategy`)
- Тик-движок расширяется: агенты принимают решения и торгуют
- `GET/POST /agents`, `GET /agents/{id}`, `.../log`, `/compare`, `/ranking`,
  `WS /ws/agents/activity`
- Мастер создания агента на фронте начинает реально отправлять данные
  (сейчас `CreateAgentScreen.tsx` и `AgentSetupTypeScreen.tsx` — форма в
  никуда)
- **Готово, когда:** экран Агенты показывает реальных агентов, реально
  торгующих на synthetic-рынке, Журнал заполняется настоящими решениями.

## Phase 5 — Симуляции

- `SimulationDataset`, `Simulation`, `SimulationResult`
- Backtest-раннер поверх тех же `Strategy`-реализаций (см.
  `03-market-data-and-agents-engine.md`, раздел про live vs backtest)
- Upload датасета, запуск, live-статус через WS, результаты, экспорт
- **Готово, когда:** можно запустить симуляцию на историческом датасете и
  увидеть результат — без `tradingExtra.ts: simDatasets/simResults`.

## Phase 6 — Команды

- `Team`, `TeamMembership`
- Лента команды = `AgentDecisionLog`, отфильтрованный по агентам участников
- **Готово, когда:** экраны Команды показывают реальные команды и реальную
  ленту, не `psychologyData.ts: teams/feedEvents`.

## Phase 7 — Настройки

- `UserSettings` (jsonb-секции) + смена пароля
- Семь settings-эндпоинтов из `02-api-contract.md`
- **Готово, когда:** изменения в настройках переживают перезагрузку
  страницы (сейчас это просто локальный React state, никуда не сохраняется).

## Phase 8 — Реальные рыночные данные (опционально для "продукт работает")

- `FinnhubMarketDataProvider`, переключатель в `/settings/data`
- Кэширование котировок (не бить лимит 60/мин на каждого зрителя —
  один поток от Finnhub, broadcast всем WS-подписчикам бэкенда, а не
  запрос на пользователя)
- **Не делай эту фазу раньше седьмой.** Реализм цен — это полировка, а не
  функциональность. Если тянет сделать её раньше "потому что интереснее" —
  это и есть подмена реального прогресса ощущением прогресса.

## Phase 9 — Твёрдость

- Валидация входных данных везде (Bean Validation), консистентные коды
  ошибок
- Rate limiting на публичных эндпоинтах (хотя бы на auth)
- Интеграционные тесты через Testcontainers на критичных путях: расчёт
  ордера, тик-движок агента, auth-флоу
- Логирование/базовое наблюдение (хотя бы структурированные логи + один
  дашборд метрик, не обязательно Prometheus/Grafana с первого дня)
- CORS настроен под реальный домен Vercel, не `*`
- **Готово, когда:** можешь показать продукт незнакомому человеку и он не
  сломает его за пять минут случайными кликами.

## Критерий "MVP закрыт"

Все 9 фаз готовы, ни один экран `apps/web/app/(app)/**` не импортирует
`fixtures.ts`, `agentsData.ts`, `tradingExtra.ts`, `psychologyData.ts` для
данных (только типы, если решишь их переиспользовать как DTO-контракты —
это нормально, отличие в том, что данные приходят с бэкенда, а не из
константы в файле).
