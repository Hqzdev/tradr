# Агенты: подробная реализация

## Создание

`AgentProvisioner` отвечает только за атомарное создание набора:

- Agent со статусом PAUSED;
- AgentConfig;
- AgentWallet;
- первая AgentEquityPoint;
- списание выделенной суммы из резерва Account.

Если резерв меньше бюджета, не создаётся ничего.

## Старт и пауза

`start` переводит агента в ACTIVE и записывает событие. `pause` переводит в
PAUSED, но не продаёт открытые позиции. Это позволяет остановить новые
решения и изучить текущее состояние.

## Allocation

Бюджет меняется только у PAUSED-агента.

- увеличение списывает разницу из резерва;
- уменьшение возвращает только свободную сумму;
- деньги, находящиеся в открытых позициях, вернуть без продажи нельзя;
- общий капитал от перевода не меняется.

## Закрытие

`close`:

1. ставит агента на паузу;
2. продаёт все позиции по текущей учебной цене;
3. возвращает остаток кошелька в Account;
4. переводит агента в ARCHIVED;
5. сохраняет сделки и решения.

Архивный агент не показывается в обычном списке и не запускается повторно.

## Performance

Ответ включает:

- начальный бюджет;
- свободные деньги;
- стоимость позиций;
- полный капитал агента;
- абсолютный и процентный P&L;
- список позиций;
- до 100 последних точек кривой капитала.

## Решение на тике

`AgentService.onTick` получает один инструмент и один снимок цены. Для
каждого ACTIVE-агента он проверяет настройку ускорения Account, затем
вызывает `evaluate`.

Продажа всегда проверяется раньше новой покупки. Это не даёт лимиту позиций
заблокировать защитный выход.

## Объяснимость

Каждый запуск, пауза, покупка, продажа и важное ожидание записываются в
AgentDecisionLog. Пользователь видит причину, но не получает обещание
будущей доходности.
