# Архитектура TRADR

TRADR разделён на фронтенд, API и локальную инфраструктуру. Каждый слой имеет собственную ответственность и может развиваться независимо.

## Компоненты

```text
Пользователь
    │
    ▼
Next.js (apps/web)
    │ REST / WebSocket
    ▼
Spring Boot (apps/backend)
    │
    ├── рынок: инструменты, свечи, котировки
    ├── dashboard: цель, резерв, общий капитал
    ├── торговля: агентские заявки и сделки
    ├── агенты: стратегии, кошельки, позиции
    └── авторизация и общий API-слой
    │
    ▼
PostgreSQL + Flyway
```

## Фронтенд

`apps/web` — приложение на Next.js. Оно показывает Dashboard, агентов,
read-only историю и рынок, вызывает REST API и подписывается на WebSocket.
Старые маршруты терминала и портфеля ведут на Dashboard.

Локальные адреса API задаются в `apps/web/.env.local`. Публичные переменные начинаются с `NEXT_PUBLIC_`.

## Бэкенд

`apps/backend` — Spring Boot-приложение. Код организован по предметным областям: `auth`, `market`, `trading`, `agents`, `dashboard` и `common`.

Внутри области разделяются уровни:

- `domain` — сущности и правила предметной области;
- `application` — прикладные сценарии и координация операций;
- `repository` — доступ к данным;
- `web` — HTTP/WebSocket-контракты и DTO;
- `exception` — ошибки, специфичные для области.

Такое разделение удерживает HTTP-детали и хранение данных вне бизнес-правил.

## Данные и поток операций

1. Синтетический провайдер создаёт новый шаг рынка.
2. Сервис рынка сохраняет и публикует котировки.
3. Активные агенты проверяют открытые позиции, затем сигналы покупки.
4. Торговый сервис исполняет только агентские операции и учитывает комиссию.
5. Dashboard складывает резерв, кошельки и рыночную стоимость позиций.
6. Frontend показывает результат через REST и живые котировки через WebSocket.

Схема базы данных находится в миграциях Flyway: `apps/backend/src/main/resources/db/migration/`.

## Границы ответственности

- Frontend не содержит правил расчёта баланса и исполнения сделки.
- Пользователь не может создать ручную торговую операцию.
- Бэкенд не зависит от компонентов Next.js и не отдаёт внутренние сущности напрямую.
- DTO формируют внешний контракт API.
- PostgreSQL хранит состояние; миграции фиксируют его эволюцию.

Подробнее о модели данных, API и поэтапном развитии — в [документации бэкенда](./apps/backend/docs/00-overview.md).
