# Phase 3: заявки, сделки и портфель

## Что появилось

Теперь пользователь может купить или продать акцию через backend. После сделки меняются три вещи:

1. Баланс счёта.
2. История сделок.
3. Позиция в портфеле.

Данные лежат в PostgreSQL, поэтому не пропадут после перезапуска backend.

## Новые таблицы

Миграция `V5__trading.sql` создаёт:

- `orders` — все заявки: открытые, исполненные и отменённые.
- `trades` — уже завершённые сделки.
- `positions` — акции, которые сейчас есть у пользователя.

Flyway применяет эту миграцию сам при следующем запуске `npm run dev`.

## Как считается цена

Расчёт перенесён из старого frontend в `trading/application/OrderCalculator.java`.

- Цена округляется до центов.
- Количество акции можно указать с точностью до восьми знаков.
- Комиссия равна 0.1% и округляется до цента.
- При покупке комиссия прибавляется к сумме.
- При продаже комиссия вычитается из суммы.

Тест `OrderCalculatorTest` повторяет сценарии старого frontend: покупка количеством, покупка на сумму, продажа, дробные акции и пограничные округления.

## API

Все методы ниже требуют заголовок `Authorization: Bearer <accessToken>`.

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/v1/orders/preview` | Считает заявку, но не сохраняет её. |
| POST | `/api/v1/orders` | Создаёт заявку. Рыночная исполняется сразу. |
| GET | `/api/v1/orders` | Показывает заявки пользователя. |
| DELETE | `/api/v1/orders/{id}` | Отменяет открытую лимитную заявку. |
| GET | `/api/v1/trades` | Показывает историю сделок. |
| GET | `/api/v1/trades/stats` | Показывает статистику сделок за сегодня. |
| GET | `/api/v1/portfolio` | Показывает баланс, стоимость портфеля и позиции. |
| GET | `/api/v1/portfolio/{ticker}` | Показывает одну позицию и её историю сделок. |

### Предварительный расчёт

```bash
curl -s -X POST localhost:8080/api/v1/orders/preview \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"ticker":"AAPL","side":"buy","anchor":"amount","value":"1000"}' | jq
```

В `anchor` передаётся `quantity`, если пользователь ввёл число акций, или `amount`, если он ввёл сумму в долларах.

### Рыночная покупка

```bash
curl -s -X POST localhost:8080/api/v1/orders \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"ticker":"AAPL","side":"buy","orderType":"market","quantity":"2"}' | jq
```

Можно передать `amount` вместо `quantity`, но не оба поля сразу.

### Лимитная заявка

```bash
curl -s -X POST localhost:8080/api/v1/orders \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"ticker":"AAPL","side":"buy","orderType":"limit","quantity":"2","limitPrice":"180"}' | jq
```

Покупка ждёт цену не выше `limitPrice`; продажа ждёт цену не ниже неё. Пока заявка ждёт, она видна в `GET /api/v1/orders?status=open`. При достижении цены её проверяет тик-движок рынка и исполняет.

## Проверка после запуска

1. Зарегистрируй нового пользователя и сохрани `accessToken`.
2. Выполни предварительный расчёт.
3. Создай рыночную покупку.
4. Запроси `/api/v1/portfolio` и убедись, что в `holdings` появилась акция.
5. Запроси `/api/v1/trades` и убедись, что появилась сделка.
6. Создай лимитную заявку далеко от текущей цены, запроси список открытых и отмени её через `DELETE`.

## Что пока не проверено через экран

Backend и база готовы. Рабочие файлы frontend сейчас удалены из дерева проекта, поэтому подключение экрана Терминала, Портфеля и Истории к этим API нельзя проверить до восстановления frontend. API можно полностью проверить командами выше.
