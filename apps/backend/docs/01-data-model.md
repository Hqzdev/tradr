# Модель данных TRADR

Ниже описана текущая схема простым языком. Источник правды — миграции в
`src/main/resources/db/migration` и Java Entity.

## Пользователь и счёт

### users

- `id` — UUID пользователя;
- `email` — уникальный e-mail;
- `password_hash` — BCrypt-хэш пароля;
- `display_name` — отображаемое имя;
- `created_at` — время регистрации.

Исходный пароль никогда не хранится.

### refresh_tokens

- принадлежит пользователю;
- хранит SHA-256-хэш токена;
- имеет дату окончания и дату отзыва.

### accounts

- `cash_balance` — резерв, ещё не переданный агентам;
- `currency` — сейчас USD;
- `goal_value` — желаемая общая сумма;
- `acceleration_enabled` — скорость работы всех агентов.

Новый счёт начинает со 100 000 USD, целью 110 000 USD и включённым
ускорением.

## Рынок

### instruments

Хранит тикер, название компании, биржу, тип и валюту. После V11 в каталоге
18 акций NASDAQ и NYSE.

### candles

Одна строка — одна OHLCV-свеча:

- open, high, low, close;
- volume;
- timeframe;
- время начала интервала;
- ссылка на инструмент.

### index_quotes

Учебные значения индексов для рыночной сводки.

## Агент

### agents

- принадлежит одному account;
- имеет имя и стратегию;
- хранит статус `ACTIVE`, `PAUSED`, `ERROR` или `ARCHIVED`;
- хранит риск и исторический trigger percent.

### agent_configs

JSON-настройки `character`, `budget` и `skills`. Бюджет имеет форму:

```json
{ "limit": 75000, "currency": "USD" }
```

### agent_wallets

Отдельный кошелёк агента:

- `initial_cash` — выделенный капитал, база для P&L;
- `cash_balance` — свободные деньги;
- `realized_profit` — уже зафиксированный результат;
- `currency` — USD.

### agent_positions

Открытые позиции конкретного агента. Составной ключ включает `agent_id` и
`instrument_id`, поэтому два агента могут независимо держать одну акцию.

Хранятся количество, средняя цена, шаг открытия и время обновления.

### agent_market_state

Последний торговый шаг агента по акции. Нужен для cooldown.

### agent_equity_points

Снимки свободных денег, стоимости позиций и общего капитала. Из них frontend
строит кривую результата.

### agent_decision_logs

Журнал решений BUY, SELL и WAIT. В строке есть причина, связанные правила,
заявка и время.

## Сделки

### orders

Аудит команды на покупку или продажу. Новые операции имеют source `AGENT`
и `source_agent_id`. Историческое значение `MANUAL` оставлено только для
старых записей.

### trades

Факт исполнения: направление, количество, цена, комиссия и время.

Сделка связана с Order, а через него — с агентом.

## Владение капиталом

```text
User
 └─ Account
     ├─ cash_balance: резерв
     └─ Agent[]
         ├─ AgentWallet: свободные деньги
         └─ AgentPosition[]: акции по текущей цене
```

Общий капитал = резерв + деньги агентов + рыночная стоимость позиций.
Перевод между резервом и агентом не является прибылью.

## Точность

- деньги — `numeric` в PostgreSQL и `BigDecimal` в Java;
- деньги обычно имеют scale 2;
- количество акций имеет scale до 8;
- время хранится как `timestamptz` / `Instant`;
- идентификаторы — UUID.

## Удалённые модели

Старые таблицы `simulations`, `simulation_datasets` и
`simulation_results` удалены миграцией V9. Они не должны появляться в новых
контрактах до отдельного возвращения backtest-функции.
